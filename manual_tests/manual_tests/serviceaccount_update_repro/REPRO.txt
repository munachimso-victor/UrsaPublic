Manual repro: ServiceAccount warm list-field updates do not downsync to edges
=============================================================================

Self-contained bug submission bundle. All paths below are relative to this
folder:

  manual_tests/serviceaccount_update_repro/


Goal
----
Reproduce KubeStellar downsync gap for ServiceAccount **list-field** updates on a
warm cluster (object already exists on edges):

  1. Apply baseline ServiceAccount + BindingPolicy on WDS; object appears on edges.
  2. Change a list field on WDS (secrets[]).
  3. WDS shows the new desired state.
  4. Edge ServiceAccount stays at the **old** state (no inventory diff / no patch).
  5. ManifestWork may still report Applied=True / Available=True (misleading).
  6. Delete ServiceAccount on the **edge only** — klusterlet recreates from hub
     ManifestWork (create path works; in-place update does not).

Metadata (labels) warm updates **do** propagate — see Step 6 (control case).


Files in this folder
--------------------
  REPRO.txt                          (this guide)
  sample.log.txt                     (example full run: setup + Steps 3–6 output)
  cleanup.sh                         (remove repro workloads from WDS + edges)

  case_label_only/                   (control — metadata propagates)
    seed.yaml, binding-policy.yaml, serviceaccount-add-label.yaml

  case_secrets_list/                 (primary repro — secrets[] grow)
    seed.yaml, binding-policy.yaml, add-second-secret.yaml

  case_combined_update/              (Step 7 — label + secrets[] + imagePullSecrets[] together)
    seed.yaml, binding-policy.yaml, combined-update.yaml

  setup_kubestellar.sh               (provision Kind + KubeStellar v0.29.0)
  create-kind-cluster-with-SSL-passthrough.sh  (used by setup_kubestellar.sh)


Sync-plane identity chain (for Steps 3–5)
-----------------------------------------
  Each downsynced object is tracked through three linked identities:

    edge ServiceAccount
      └─ ownerReference → AppliedManifestWork (cluster-scoped on edge)
            └─ spec.manifestWorkName → ManifestWork (namespace=edge-1 on its1)

  Record name + uid (+ generation for ManifestWork) at each phase and compare.
  ManifestWork lives on ITS only; AppliedManifestWork lives on the edge only.

Step 3 — Reproduce: secrets[] grow (primary case, copy/paste)
-------------------------------------------------------------
  export KUBECONFIG=~/.kube/kubeflex
  cd manual_tests/serviceaccount_update_repro   # from Ursa repo root

  NS=ursa-namespace-template
  SA=ursa-serviceaccount-template

  ./cleanup.sh
  sleep 60

  # 3a. Baseline — one secrets[] entry, initial downsync
  kubectl --context wds1 apply -f case_secrets_list/seed.yaml
  kubectl --context wds1 apply -f case_secrets_list/binding-policy.yaml

  echo "Waiting 230s (Ursa engine sync window)..."
  sleep 230

  # Baseline check — one secret on WDS and both edges
  kubectl --context wds1 get sa "$SA" -n "$NS" -o jsonpath='WDS secrets={.secrets}{"\n"}'
  kubectl --context edge-1 get sa "$SA" -n "$NS" -o jsonpath='edge-1 secrets={.secrets}{"\n"}'
  kubectl --context edge-2 get sa "$SA" -n "$NS" -o jsonpath='edge-2 secrets={.secrets}{"\n"}'

  # 3c. Snapshot sync-plane IDs BEFORE warm update (save output for Step 4 compare)
  for EDGE in edge-1 edge-2; do
    echo "=== SYNC TRACE $EDGE phase=baseline-before-warm-update ==="
    AMW_NAME=$(kubectl --context "$EDGE" get sa "$SA" -n "$NS" \
      -o jsonpath='{.metadata.ownerReferences[?(@.kind=="AppliedManifestWork")].name}')
    AMW_UID=$(kubectl --context "$EDGE" get sa "$SA" -n "$NS" \
      -o jsonpath='{.metadata.ownerReferences[?(@.kind=="AppliedManifestWork")].uid}')
    MW_NAME=$(kubectl --context "$EDGE" get appliedmanifestwork "$AMW_NAME" \
      -o jsonpath='{.spec.manifestWorkName}')
    kubectl --context its1 get manifestwork -n "$EDGE" "$MW_NAME" \
      -o jsonpath='ITS ManifestWork name={.metadata.name} uid={.metadata.uid} generation={.metadata.generation} rv={.metadata.resourceVersion}{"\n"}'
    kubectl --context "$EDGE" get appliedmanifestwork "$AMW_NAME" \
      -o jsonpath='edge AppliedManifestWork name={.metadata.name} uid={.metadata.uid} rv={.metadata.resourceVersion}{"\n"}'
    kubectl --context "$EDGE" get sa "$SA" -n "$NS" \
      -o jsonpath='edge ServiceAccount uid={.metadata.uid} rv={.metadata.resourceVersion}{"\n"}'
  done

  # 3b. Warm update — grow secrets[] on WDS only
  kubectl --context wds1 apply -f case_secrets_list/add-second-secret.yaml

  echo "Waiting 230s for downsync..."
  sleep 230


Step 4 — Verify the bug (copy/paste)

      -o jsonpath='{.metadata.ownerReferences[?(@.kind=="AppliedManifestWork")].name}')

      -o jsonpath='{.spec.manifestWorkName}')
    kubectl --context its1 get manifestwork -n "$EDGE" "$MW_NAME" \
      -o jsonpath='ITS ManifestWork name={.metadata.name} uid={.metadata.uid} generation={.metadata.generation} observedGen={.status.conditions[?(@.type=="Applied")].observedGeneration} rv={.metadata.resourceVersion}{"\n"}'
    kubectl --context its1 get manifestwork -n "$EDGE" "$MW_NAME" \
      -o jsonpath='ITS MW Applied={.status.conditions[?(@.type=="Applied")].status} Available={.status.conditions[?(@.type=="Available")].status}{"\n"}'
    kubectl --context "$EDGE" get appliedmanifestwork "$AMW_NAME" \
      -o jsonpath='edge AppliedManifestWork name={.metadata.name} uid={.metadata.uid} rv={.metadata.resourceVersion}{"\n"}'
    kubectl --context "$EDGE" get sa "$SA" -n "$NS" \
      -o jsonpath='edge ServiceAccount uid={.metadata.uid} rv={.metadata.resourceVersion}{"\n"}'

  SUCCESS CRITERIA:
    WDS ServiceAccount secrets[] has ursa-opaquesecret-template AND
      ursa-basicauthsecret-template

    ITS ManifestWork: name + uid UNCHANGED vs baseline; generation INCREASED
    edge AppliedManifestWork: name + uid UNCHANGED vs baseline
    edge ServiceAccount: uid UNCHANGED vs baseline (same object, stale spec)
    ManifestWork Applied=True, Available=True despite stale edge spec

What NOT to do
--------------
  - Run kubectl without KUBECONFIG=~/.kube/kubeflex (edge-* / wds1 contexts live there)
  - Apply manifests from the Ursa repo root (use this folder; paths are relative)
  - Look for ManifestWork on edge clusters (use its1 for ManifestWork, edge for live SA)
  - Delete ServiceAccount on wds1 when testing edge-delete recovery (delete on edges only)
  - Use clusteradm v1.x with KubeStellar 0.29 hub (token SA mismatch)
  - Expect monolith Ursa run to fail — use __pert_* slices or this manual repro


Expected behaviour
------------------
  After a warm update on WDS, BindingPolicy/ManifestWork should patch the existing
  ServiceAccount on bound edges so hub and edge converge for both metadata and
  spec list fields (secrets[]).

  Bug classification:
    - metadata (labels):      warm UPDATE works (Step 6 control)
    - spec list fields:       warm UPDATE fails (Steps 3–4)
    - combined apply:         metadata propagates, list fields stale (Step 7)
    - edge delete + recreate: CREATE from hub ManifestWork works (Steps 5, 8)

  Ursa ledger text on automated runs:
    No add/update in inventory diff for seed-changed object(s):
      [('ServiceAccount', 'ursa-namespace-template/ursa-serviceaccount-template')]

  Re-run automated slice (clusters must already exist):

    cd /path/to/Ursa    # repo root containing engine.py
    python3 engine.py \
      --run-suite test_2026-06-28_02-25/run_ursa-bp-serviceaccount__pert_ursa-dockerconfigjsonsecret-template \
      --skip-setup
