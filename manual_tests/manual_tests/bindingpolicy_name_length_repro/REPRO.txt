Manual repro: long BindingPolicy names are not picked up by ITS (no ManifestWorks)
==================================================================================

Self-contained bug submission bundle. All paths below are relative to this
folder:

  manual_tests/bindingpolicy_name_length_repro/

Goal
----
Reproduce KubeStellar transport failure when a BindingPolicy ``metadata.name``
exceeds a length threshold:

  1. Apply a simple workload (Namespace + ConfigMap) on WDS.
  2. Apply a BindingPolicy with a **long** name that downsyncs that workload.
  3. BindingPolicy **exists on WDS** (desired state is accepted).
  4. ITS (**its1**) never creates ManifestWorks for the bound objects.
  5. Edges never receive the ConfigMap / Namespace.

Automated evidence: ``tests/test_2026-06-25_00-27`` — policies with catalog-style
names longer than ~63 characters fail ManifestWork coverage while shorter names pass.

Ursa already shortens generated policy names in ``testcase_builder.py``
(``format_binding_policy_name()``) because long names "break KubeStellar transport
labels".

Step 5 — Find exact length boundary (copy/paste)
------------------------------------------------
  Use padded names ``bp-len-probe-`` + ``a`` characters to hit an exact length.
  The helper script applies one policy at a time, waits, and checks sync.

  Important:
    - ``probe_length.sh`` resets edge namespaces between probes so stale ConfigMaps
      do not look like a PASS.
    - Binding cleanup uses **exact** policy names (shorter ``bp-len-probe-`` names
      are prefixes of longer ones — never grep-substring bindings).
    - ITS check uses ``-l transport.kubestellar.io/originOwnerReferenceBindingKey=<name>``
      and counts rows with ``--no-headers`` (not ``grep '^kind: ManifestWork'``).

  export KUBECONFIG=~/.kube/kubeflex
  cd manual_tests/bindingpolicy_name_length_repro
  chmod +x probe_length.sh cleanup.sh

  ./cleanup.sh && sleep 60
  kubectl --context wds1 apply -f workload.yaml

  # Single probe (example: 63 characters)
  ./probe_length.sh 63

  # Linear sweep 58–70 (records last PASS and first FAIL)
  ./probe_length.sh --sweep 58 70

  # Binary search between known-good and known-bad range
  ./probe_length.sh --binary 58 70

  PASS criteria (transport reached ITS):
    - ``wds Binding object: 1`` in probe output (``bindings.control.kubestellar.io``)
    - ``its1 MW count (this policy): 2`` via label
      ``transport.kubestellar.io/originOwnerReferenceBindingKey=<policy-name>``
    - ConfigMap present on edge-1

  FAIL / bug signature (length >= 64):
    - ``wds BindingPolicy: 1`` and ``wds Binding object: 1`` (WDS accepts policy
      and creates Binding — transport starts but does not reach ITS)
    - ``its1 MW count (this policy): 0``
    - ConfigMap / Namespace missing on edges (after edge reset between probes)

  Record your boundary in sample.log.txt (see below).


Manual probe for one length (without script)
--------------------------------------------
  export KUBECONFIG=~/.kube/kubeflex
  TARGET=63
  PREFIX="bp-len-probe-"
  PAD=$(( TARGET - ${#PREFIX} ))
  NAME="${PREFIX}$(python3 -c "print('a'*${PAD})")"
  echo "len=${#NAME} name=${NAME}"

  kubectl --context wds1 apply -f - <<EOF
  apiVersion: control.kubestellar.io/v1alpha1
  kind: BindingPolicy
  metadata:
    name: ${NAME}
  spec:
    clusterSelectors:
    - matchLabels:
        name: edge-1
    - matchLabels:
        name: edge-2
    downsync:
    - objectNames:
      - ursa-configmap-length-probe
      - ursa-namespace-length-probe
  EOF

  sleep 90

  kubectl --context wds1 get bindingpolicy "${NAME}"
  kubectl --context wds1 get bindings.control.kubestellar.io
  kubectl --context its1 get manifestworks -n edge-1 \
    -l "transport.kubestellar.io/originOwnerReferenceBindingKey=${NAME}"
  kubectl --context its1 get manifestworks -n edge-1 \
    -l "transport.kubestellar.io/originOwnerReferenceBindingKey=${NAME}" -o yaml | \
    grep -E 'kind: (Namespace|ConfigMap)|name: (ursa-namespace-length-probe|ursa-configmap-length-probe)'
  kubectl --context edge-1 get configmap -n ursa-namespace-length-probe ursa-configmap-length-probe


Step 6 — Bug: long catalog name should NOT sync (copy/paste)
------------------------------------------------------------
  export KUBECONFIG=~/.kube/kubeflex
  cd manual_tests/bindingpolicy_name_length_repro

  ./cleanup.sh
  sleep 60
  kubectl --context wds1 apply -f workload.yaml

  POLICY="ursa-dockerconfigjsonsecret-template-policy-ursa-dockerconfigjsonsecret-template"
  echo "policy name length: ${#POLICY}"

  kubectl --context wds1 apply -f case_catalog_long_name/binding-policy-fail-80.yaml

  sleep 90

  # WDS: policy exists (bug is NOT admission rejection)
  kubectl --context wds1 get bindingpolicy "${POLICY}" -o yaml

  kubectl --context wds1 get bindings.control.kubestellar.io -o wide

  # ITS: zero ManifestWorks for this policy (compare Step 4 label query)
  kubectl --context its1 get manifestworks -n edge-1 \
    -l "transport.kubestellar.io/originOwnerReferenceBindingKey=${POLICY}"
  kubectl --context its1 get manifestworks -n edge-1 \
    -l "transport.kubestellar.io/originOwnerReferenceBindingKey=${POLICY}" -o name || \
    echo "no ITS ManifestWorks for this policy (expected bug signature)"

  # Edges: objects missing
  kubectl --context edge-1 get namespace ursa-namespace-length-probe
  kubectl --context edge-1 get configmap -n ursa-namespace-length-probe ursa-configmap-length-probe

  Expected bug: WDS has BindingPolicy; ITS has no ManifestWorks for the ConfigMap
  or Namespace; edges have nothing. Same pattern as
  tests/test_2026-06-25_00-27/run_ursa-dockerconfigjsonsecret-template-policy-*.
